Classes génériques

  • Elles prennent un ou plusieurs paramètres de type, déclarés entre [...]
  • La convention est d’utiliser une seule lettre A, B, ou T pour nommer ces paramètres
  • Le paramètre de type peut ensuite être utilisé dans le corps de la classe
// Pile FIFO First In First Out
case class Stack[A](elements: List[A]):
  def push(x: A): Stack[A] =
    Stack(x +: elements)

  def peek: Option[A] =
    elements.headOption

  def pop: (Option[A], Stack[A]) =
    elements match 
      case Nil => (None, this)
      case head :: tail => (Some(head), Stack(tail))
    
val stack      = Stack[Int](List(2, 1))
val stackInfer = Stack(List(2, 1)) // 'A' est inféré
// val stackInfer: Stack[Int] = Stack(List(2, 1))

stack.push(3) // Stack(List(3,2,1))
stack.pop // (Some(2), Stack(List(1))

// le paramètre de type ne peut pas être inféré
val emptyStack: Stack[String] = Stack(List())
  • Une sous-classe doit spécifier le type réel
trait JsonEncoder[A]:
  def encode(obj: A): String
  
  
object JsonMapEncoder extends JsonEncoder[Map[String, String]]:
  override def encode(obj: Map[String, String]): String = 
    "{" +
    obj.map((key, value) => s""" "$key":"$value" """)
      .mkString(",") + 
    "}"
  
JsonMapEncoder.encode(Map("name" -> "Dupont", "firstName" -> "Martin"))  
// val res0: String = { "name":"Dupont"  , "firstName":"Martin"  }

Classes génériques - Type bounds

On peut spécifier des contraintes sur un paramètre de type :

  • A <: Upper : borne supérieure (upper type bound). A doit être une sous-classe de Upper.
  • A >: Lower : borne inférieure (lower type bound). A doit être une super-classe de Lower.
    • utilisé dans les définitions de méthodes polymorphiques (voir ci-dessous)
// Pile qui accepte uniquement des éléments Comparable
class SortedStack[T <: Comparable[T]]:
  // ...

Méthodes polymorphiques

Des paramètres de types peuvent être déclarés dans les méthodes.

Cela permet de définir des méthodes qui s’appliquent de manière très générale, sans contraindre fortement le type des paramètres.

object Utils:
  def isSorted[A](as: Seq[A], gt: (A,A) => Boolean): Boolean = ???
    
  def pair[A, B](first: A, second: B): (A, B) =
    (first, second)

  // T has an upper type bound
  def max[T <: Comparable[T]](a: T, b: T): T =
    if a.compareTo(b) > 0 then a else b

Classes génériques - Variance

Considérons ces classes :

case class Stack[A](elements: List[A])

trait Animal
class Cat extends Animal
class Dog extends Animal

On peut préciser la variance du paramètre A dans Stack[A]. Le paramètre de type peut être :

  • Invariant : [A]
    • par défaut. Stack[Animal] n’a pas de relation de sous-typage avec Stack[Dog].
  • Covariant : [+A]
    • implique que Stack[Animal] sera considérée comme une super-classe de Stack[Dog]
  • Contravariant : [-A]
    • implique que JsonEncoder[Dog] sera considérée comme une super-classe de JsonEncoder[Animal]
Note
  • La variance ne peut pas être spécifiée dans les méthodes polymorphiques. Elle s’exprime uniquement pour les classes et traits.
  • Les classes mutables doivent être invariantes.

Covariance [+A]

À utiliser lorsque la classe générique produit des A : Collections, Décodeurs, Cache

val dogs: Stack[Dog] = Stack(List(Dog()))
// on peut assigner car Stack[Dog] <:< Stack[Animal]
val animals: Stack[Animal] = dogs

val catsAndDogs = animals.push(Cat())
// val catsAndDogs: Stack[Animal] = ...
// Ne fonctionnerait pas si Stack était mutable

Contravariance [-A]

À utiliser lorsque la classe générique consomme des A : Encodeurs

trait JsonEncoder[A]:
  def encode(obj: A): String

val animalEncoder: JsonEncoder[Animal] = ???
// on peut assigner, car JsonEncoder[Animal] <:< JsonEncoder[Dog]
// si je peux encoder un Animal en Json, je sais aussi encoder Dog, Cat, ...
val dogEncoder: JsonEncoder[Dog] = animalEncoder
dogEncoder.encode(Dog())

Méthodes et variance

  • Le type de retour est en position covariante.
  • Les paramètres d’une méthode sont en position contravariante

Lorsqu’une classe est covariante [+A], A ne peut être utilisé que dans le type de retour.

case class Stack[+A](elements: List[A]):
  // OK, A est en position covariante
  def peek: Option[A] = ???

  // ERREUR DE COMPILATION !! x: A est en position contravariante !
  def push(x: A): Stack[A] = ???

Lorsqu’une classe est contravariante [-A], A ne peut être utilisé que dans les paramètres.

trait JsonDecoderEncoder[-A]:
  // OK, A est en position contravariante
  def encode(obj: A): String
  
  // ERREUR DE COMPILATION !! A est en position covariante !
  def decode(json: String): A

Méthodes et variances — pourquoi ?

Ces contraintes garantissent que le système de typage est cohérent. (the type system is sound)

Covariance absurde

Prouvons que les paramètres sont contravariants par l’absurde. Imaginons que le compilateur autorise ceci :

trait Animal
case class Dog(woof: String) extends Animal
case class Cat(miaw: String) extends Animal

trait Encoder[+A]:
  // ❌ Interdit : A est en position contravariante
  def encode(a: A): String

object DogEncoder extends Encoder[Dog]
  def encode(a: Dog): String =
    a.woof

Alors, on pourrait se retrouver dans la situation suivante :

// on peut assigner. A est covariant, donc Encoder[Dog] <:< Encoder[Animal]
val animalEncoder: Encoder[Animal] = DogEncoder
// ❌ Absurde !! encode ne peut prendre en paramètre que Dog ou ses sous-classes
animalEncoder.encode(Cat("miaou"))

Contravariance absurde

Prouvons que le type résultat est covariant. Imaginons que le compilateur autorise ceci :

trait Decoder[-A]:
  // ❌ Interdit : A est en position covariante
  def decode(s: String): A

object AnimalDecoder extends Decoder[Animal]
  def decode(s: String): Animal =
    if (s == "miaou") Cat(s) else Dog(s)

Alors, on pourrait se retrouver dans la situation suivante :

// on peut assigner. A est contravariant, donc Decoder[Animal] <:< Decoder[Dog]
val dogDecoder: Decoder[Dog] = AnimalDecoder
// ❌ Absurde !! decode renvoie une instance de Cat
val dog: Dog = dogDecoder.decode("miaou")

Collections contravariantes — méthodes d’ajout

Étant donné les contraintes sur les paramètres, comment implémenter notre classe Stack ?

case class Stack[+A](elements: List[A]):
  // ❌ Interdit : A est en position covariante
  def push(x: A): Stack[A] =
    Stack(x +: elements)

L’astuce est d’utiliser une méthode polymorphique avec une borne inférieure :

case class Stack[+A](elements: List[A]):
  // ✅ Compile : B est un paramètre de type
  // Il peut être égal à A ou être une super-classe de A
  def push[B >: A](x: B): Stack[B] =
    Stack(x +: elements)

Le compilateur infère le type B lorsqu’on appelle push. Il cherche la super-classe la plus proche qui est commune à A et au type du paramètre passé.

Utilisation :

trait Animal
case class Dog(name: String) extends Animal
case class Cat(name: String) extends Animal

val dogStack = Stack(List(Dog("Winnie"), Dog("Dolly")))
// val dogStack: Stack[Dog] = Stack(List(Dog(Winnie), Dog(Dolly)))

// B est inféré, égal à Dog
val dogStack2 = dogStack.push(Dog("Upi"))
// val dogStack2: Stack[Dog] = Stack(List(Dog(Upi), Dog(Winnie), Dog(Dolly)))

// B est inféré, égal à Animal
val animalStack = dogStack.push(Cat("Max"))
// val animalStack: Stack[Animal] = Stack(List(Cat(Max), Dog(Winnie), Dog(Dolly)))

// B est inféré, égal à Animal | Int
val objectStack = animalStack.push(1)
// val objectStack: Stack[Animal | Int] = ...
