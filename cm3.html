Récursion

  • En langage purement fonctionnel, on ne peut pas modifier une variable : tout est immutable.
  • Comment peut-on écrire une boucle avec une variable i qui change à chaque itération ?
  • Utiliser la récursion !

Récursion stack-unsafe

def somme(n: Int): Int =
  if n <= 0 then
    0
  else
    n + somme(n - 1)
  • problème : chaque appel consomme de la mémoire dans la pile.
  • OK jusqu’à une centaine d’appels
  • somme(100000) => StackOverFlowError

Récursion stack-safe

  • Lorsque l’appel récursif est le dernier appel de la fonction, le compilateur peut transformer l’appel en une boucle itérative.
  • l’appel est en dit en “tail position”
  • on peut annoter la fonction @tailrec pour garantir que l’optimisation a lieu. Le compilateur génèrera une erreur s’il ne peut pas optimiser.
@tailrec
def somme(n: Int): Int =
  if n <= 0 then
    0
  else
    n + somme(n - 1)
/*
6 |    n + somme(n - 1)
  |        ^^^^^^^^^^^^
  |        Cannot rewrite recursive call: it is not in tail position
*/
  • le dernier appel n’est pas somme mais +.
  • il faut introduire une fonction loop interne
def somme(n: Int): Int = 
  @tailrec
  def loop(acc: Int, i: Int): Int =
    if i <= 0 then // condition de sortie
      acc // renvoie la donnée accumulée
    else 
      loop(acc + i, i - 1)
    
  loop(0, n)

La fonction est optimisée avec une boucle semblable à ceci :

def sommeImperative(n: Int): Int =
  var acc = 0
  var i = n
  while !(i <= 0) do
    acc = acc + i
    i = i - 1
  acc

Collections

  • package scala.collection
  • Interfaces les plus utilisées :
    • Seq[T] pour une séquence d’objets
    • Map[K, V] pour les dictionnaires
    • Set[T] pour un ensemble garantissant l’unicité
  • Elles prennent un ou 2 paramètre(s) de type [T] (voir CM4)

Collections Mutable

  • package scala.collection.mutable
  • On privilégie le style fonctionnel
    • => à éviter, sauf pour optimiser les performances
  • Array[T] est représenté comme un tableau Java
val arr = Array(1, 2, 3)
arr(0) = 2
println(arr(0)) // 2
println(arr.length) // 3
  • mutable.ArraySeq[T] implémente Seq. Taille fixe. En cas d’ajouts/suppression, une copie est effectuée
  • mutable.ArrayBuffer[T] se comporte comme un ArrayList en Java
  • mutable.ListBuffer[T] se comporte comme une LinkedList en Java
  • mutable.HashMap[K, V] se comporte comme une HashMap en Java

Collections Immuable

  • package scala.collection.immutable
  • Importées par défaut si on n’importe pas les collections mutables.
  • les méthodes qui modifient la collection renvoient une nouvelle collection
  • ce sont des collections persistantes
    • elles préservent la version précédente lorsqu’elles sont modifiées
  • les implémentations sont efficaces et ne dupliquent pas complètement les données

Séquences Immuables - implémentations

  • List est une liste chaînée.
  • par défaut, lorsqu’on construit une Seq, on a une List
  • Vector est un arbre large et peu profond
    • performant pour la plupart des opérations
    • radix-balanced finger tree of width 32
val seq = Seq(1, 2, 3) // val seq: Seq[Int] = List(1, 2, 3)

Tip

Utiliser Seq pour le code standard avec moins de 1000 éléments. Basculer sur Vector ou List en fonction des usages.

Sets immuables - implémentations

  • Set(1, 2, 3) => utilise HashSet par défaut
  • TreeSet pour conserver un ordre

Dictionnaires immuables - implémentations

  • Map => utilise HashMap par défaut (sauf pour moins de 5 clés)
  • ListMap conserve l’ordre d’insertion
  • SortedMap garde les clés triées, et est implémentée par TreeMap

Légende

  • O(1) = Temps constant
  • O(1)eff = Temps effectivement constant (comme le log32 n de Vector)
  • O(1)am = Temps constant amorti (occasionnellement plus lent, mais constant en moyenne)
  • O(log n) = Temps logarithmique
  • O(n) = Temps linéaire
  • - = Opération non supportée

Guide de décision rapide

Tip

Besoin d’accès aléatoire rapide ? → Vector ou ArrayBuffer
Beaucoup d’ajouts en début ? → List ou ListBuffer
Beaucoup d’ajouts en fin ? → ArrayBuffer ou Vector
Recherche clé-valeur ? → HashMap (immuable ou mutable)
Besoin d’ordre trié ? → TreeSet ou TreeMap

Collections - opérations

Création et Ajout

val seq = Seq(1, 2, 3)
val seq2 = seq :+ 4 // seq.appended(4) => Seq(1, 2, 3, 4)
val seq3 = 0 +: seq // seq.prepended(0) => Seq(0, 1, 2, 3, 4)
val seq4 = seq3 ++ Seq(5, 6) // Seq(0, 1, 2, 3, 4, 5, 6)

// syntaxe tuple: (clé, valeur) ou clé -> valeur
val map = Map("a" -> 65, "b" -> 66, "c" -> 67)
val map2 = map + (("d", 68)) // Map(a -> 65, b -> 66, c -> 67, d -> 68)
  • comment se rappeler de +: et :+ ?
    • le : est du côté du Seq

Suppression

val seq = Seq(1, 2, 3)
seq.tail // Seq(2, 3)

val set = Set(1, 2, 3, 3, 1)

val map = Map("a" -> 1, "b" -> 2, "c" -> 3)
map - "b" // Map(a -> 1, c -> 3)

seq.drop(2) // Seq(3)

Accès

seq.head // "début"

Collections - higher order functions

Function as value

  • !! Le mot-clé def définit une méthode
  • Une fonction est une valeur qui peut être affectée à une variable, ou passée en paramètre.
  • Son type est de la forme :
    • ParamType => ResultType
    • (Param1Type, Param2Type, ...) => ResultType
    • Param1Type => Param2Type => ... => ResultType : currying
  • Le type peut être inféré si le compilateur a assez d’informations
  • Sa définition prend les formes suivantes :
    • param => Body lorsque ParamType peut être inféré
    • (param: ParamType) => Body
    • (param1, param2, ...) => Body lorsque Param1Type et Param2Type peuvent être inférés
    • (param1: Param1Type, param2: Param2Type, ...) => Body
    • (param1: Param1Type) => (param2: Param2Type) => ... => Body : currying
    • Body contenant des caractères _. Chaque _ correspond à un paramètre
// le type de la variable "mult" est inféré
val mult                  = (x: Int) => x * 2  // val mult: Int => Int 
// le type du paramètre x est inféré à l'aide du type de la variable "multInfer"
val multInfer: Int => Int = x => x * 2         // val multInfer: Int => Int 
val multShort: Int => Int =      _ * 2         // val multShort: Int => Int 

val addXY                         = (x: Int, y: Int) => x + y     // val addXY: (Int, Int) => Int
val addXYInfer: (Int, Int) => Int = (x, y) => x + y               // val addXYInfer: (Int, Int) => Int
val addXYShort: (Int, Int) => Int = _ + _                         // val addXYShort: (Int, Int) => Int

// currying : fonction qui renvoie une fonction qui renvoie un résultat
val addXYCurry                       = (x: Int) => (y: Int) => x + y // val addXYCurry: Int => Int => Int
val addXYCurryInf: Int => Int => Int = x => y => x + y               // val addXYCurryInf: Int => Int => Int

// appel d'une fonction "curried"
addXYCurry(2)(3) // 5
// la fonction est partiellement appliquée, pour le paramètre x uniquement
val addY = addXYCurry(2) // val addY: Int => Int 
addY(3) // 5

Transformation

Transformation de Seq ou Set :

val seq = Seq(1, 2, 3)
seq.map(x => x * 2) // List(2, 4, 6)
seq.map(_ + 1) // List(2, 3, 4)

seq.filter(_ % 2 == 0) // List(2)
// les valeurs sont filtrées à la demande (lazy evaluation)
val seq2 = seq.withFilter(_ % 2 == 0) // seq2: WithFilter[Int, Seq] = ...
// il faut appeler map pour forcer l'évaluation
seq2.map(x => x) // List(2)

// aplatir après transformation
seq.flatMap(x => Seq(x, x * 2))     // List(1, 2, 2, 4, 3, 6)
seq.map(x => Seq(x, x * 2)).flatten // List(1, 2, 2, 4, 3, 6)

// collect = filter + map
seq.collect:
  case x if x % 2 == 0 => x * 2

Transformation de Map :

val m = Map("a" -> 1, "b" -> 2, "c" -> 3)
// les valeurs sont transformées à la demande (lazy evaluation)
val m2 = m.view.mapValues(v => v * 2) // scala.collection.MapView[String, Int]
// force la création d'une nouvelle map
val m3 = m2.toMap // Map[String, Int] = Map(a -> 2, b -> 4, c -> 6)

// transforme les clés et les valeurs
m.map((k, v) => k + k -> v * 2) // Map(aa -> 2, bb -> 4, cc -> 6)

val sum = seq.reduce(_ + _) // !! exception si collection vide

val words = Seq("Hello", "Scala", "World")

Boucles

Le for de Scala est un “sucre syntaxique” - il facilite l’écriture, mais on peut toujours le remplacer par une suite d’opérations - toute expression for peut être remplacée par une suite de map, flatMap, filter

foreach

val nums = Seq(1,2,3)
for n <- nums do
  print(n.toString + "; ") // 1; 2; 3
  
// équivalent "desugared" 
nums.foreach(n => n.toString + "; ")

foreach - générateurs

for
  i <- 1 to 2
  j <- 'a' to 'b'
  k <- 1 to 10 by 5
do
  println(s"i = $i, j = $j, k = $k")

for-yield

val list =
  for i <- 10 to 12
  yield i * 2
// Vector(20, 22, 24)
    
// desugared
val list2 = (10 to 12).map(i => i * 2)
val result = 
  for 
    x <- List(1, 2, 3)
    y <- List(10, 20)
  yield x + y

// desugared
val result2 = List(1, 2, 3).flatMap(x => List(10, 20).map(y => x + y)

for-yield avec if

for
  i <- 1 to 10
  if i > 3
  if i < 6
yield i 
// Vector(4, 5)

// desugared
(1 to 10).withFilter(_ > 3).withFilter(_ < 6).map(x => x)

while

var i = 0

while i < 3 do
  println(i)
  i += 1
